# Разработка

Команды выполняются из корня репозитория. Python 3.12 рекомендуется для локальной
разработки; создайте отдельное виртуальное окружение и установите `requirements.txt`.
Для тестов токен не нужен; реальные заявки не отправляются.

```bash
python -m unittest discover -s trading_bot/tests -q
python -m compileall -q trading_bot tools
python -m pip check
python tools/check_publication.py
```

Форматирование:

```bash
python -m pip install -r trading_bot/requirements-dev.txt
python -m black trading_bot tools
```

Прежде чем изменять стратегию, сохраните гипотезу, заранее выбранные параметры,
периоды и затраты. Не выбирайте победителя по проверочному участку. Добавляйте
проверки причинности сигналов, комиссий, повторных котировок и восстановления
состояния. Новые алгоритмы не должны автоматически включать отправку заявок.

При изменениях исполнения проверяйте идентификаторы запросов, сверку с брокером,
незавершённые операции и лимиты. Не повторяйте заявку после неоднозначной сетевой
ошибки. Публичные тестовые данные должны быть синтетическими и обезличенными.

CI проверяет тесты на нескольких версиях Python, публикационные файлы, сборку
Docker-образа, тесты внутри него и доступность локального HTTP-сервера. В CI нет
настоящего токена: ошибки загрузки рыночных данных допустимы в smoke-запуске
панели, проверяется HTTP-сервис, а не доступ к брокеру.

Перед публикацией создайте источник-архив:

```bash
python tools/export_source.py
```

Проверьте список файлов в `dist/trading-robot-source.zip`. Если добавили новый
тип исходников, обновите разрешённые пути в `tools/check_publication.py` и
`.dockerignore`. Не добавляйте секреты или рабочие данные даже в тестовую ветку.
Лицензия, авторство и имя GitHub-репозитория выбираются владельцем проекта.
