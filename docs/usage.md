# Руководство пользователя

Команды выполняются из корня репозитория после установки зависимостей.
Сначала настройте `trading_bot/.env` по пустому шаблону.

## Режимы

| Режим | Что происходит |
|---|---|
| Панель | Загружает данные и показывает состояние; сама не запускает стратегию |
| Наблюдение | Записывает решения стратегии, не отправляет заявки |
| Бумажная торговля | Создаёт виртуальные сделки по текущим котировкам; брокерские счета не изменяет |
| Sandbox-исполнение | Отправляет виртуальные заявки брокеру, с отдельными разрешениями |
| Бэктест | Моделирует сделки на сохранённой/загруженной истории |

Бумажный режим использует рыночные данные Sandbox API, поэтому для него тоже
нужен токен и интернет. Остановка сохраняет открытую виртуальную позицию.
После запуска ждёт новую закрытую свечу и не покупает задним числом.

## CLI

```bash
python trading_bot/main.py info
python trading_bot/main.py panel
python trading_bot/main.py bot --profile ma_sber --loop
python trading_bot/main.py backtest --profile ma_sber --days 90
python trading_bot/main.py backtest --profile ma_sber --from-date 2026-01-01 --to-date 2026-03-31
python trading_bot/main.py backtest --replay trading_bot/reports/ИМЯ_ПАПКИ
python trading_bot/main.py --help
```

В наблюдении читаются данные и записываются решения; для Sandbox-профиля может
создаваться отдельный виртуальный счёт. `--execute` добавляет отправку заявок.
Её разрешают только вместе `ENABLE_SANDBOX_ORDERS=true`,
`ENABLE_AUTO_TRADING=true` и явный запуск исполнения. По умолчанию всё выключено.
Для одиночных команд `order` и `smoke` нужен `ENABLE_SANDBOX_ORDERS=true`.
Эти команды действительно меняют виртуальный Sandbox-портфель.

Прежние команды без `--profile` используют отдельное старое состояние/счёт.
Не смешивайте их с профильными запусками. В CLI профиль передаётся явно.

## Профили стратегий

Профиль объединяет один инструмент и настройки алгоритма. Создать его можно
в панели или импортировать JSON; произвольный исполняемый код не загружается.

```json
{
  "id": "my_lkoh",
  "name": "Мой эксперимент LKOH",
  "ticker": "LKOH",
  "initial": 200000,
  "fee_bps": 5,
  "slippage_bps": 5,
  "params": {
    "kind": "ma",
    "fast": 10,
    "slow": 30,
    "trend": 0,
    "entry_edge_bps": 0,
    "stop_pct": 1
  }
}
```

ID уникален; существующий профиль нельзя перезаписать импортом. Изменённые
параметры требуют нового ID для сохранённой бумажной сессии, чтобы результат
старых правил не смешивался с новыми. Профиль хранится в `strategy_profiles/`.

| `kind` | Правила |
|---|---|
| `ma` | Пересечение средних `fast`/`slow`; необязательный фильтр `trend` |
| `breakout` | Вход выше максимума предыдущих `slow` закрытий, выход ниже минимума `fast` |
| `reversion` | Отклонение ниже средней `slow` на 2σ, RSI(`fast`) ≤30; выход к средней |
| `pullback` | RSI(`fast`) ≤10; выход к средней `slow` |

Интервал профильных стратегий — **15 минут**, рублёвые акции; исполнение
ограничено классом TQBR. `entry_edge_bps` ограничивает минимальное отклонение
сигнала: 5 bps = 0,05%. В откатах `trend` проверяет цену выше средней и рост
между половинами этого окна; RSI использует простые суммы изменений закрытий,
без сглаживания Wilder. Новые откатные профили экспериментальные.

Лимиты профильного робота: 1 лот, максимум 5% капитала, до 2 входов и 4 попыток
в день, дневной предел потерь 1%. Если лот дорогой, вход пропускается. Стоп
`stop_pct` программный: не гарантирует цену выхода или непрерывную защиту.
Нельзя обходить ограничения, чтобы получить больше сделок в тесте.

## Что учитывают модели

Исторический тест использует завершённые свечи. Сигнал закрытия исполняется
на следующем открытии; стоп моделируется по OHLC с учётом разрыва цены.
Бумажная сделка — по свежей текущей котировке с заданными затратами. Повторные
котировки не создают повторных сделок; котировки старше 120 секунд блокируют
новые операции. Цены проверяются примерно раз в 30 секунд.

Комиссия и проскальзывание учитываются с обеих сторон. Открытая позиция
оценивается по последней цене, без будущей комиссии продажи. Стакан, очередь
заявок, частичные исполнения, дивиденды, налоги и доход на свободные деньги
в исторической и бумажной моделях не учитываются. Прошлая доходность не
подтверждает будущую прибыль. Последняя цена может возвращаться при закрытых
торгах: это не означает доступность отправки заявки.

## Исследования

```bash
python trading_bot/research.py trading_bot/reports/ИМЯ_ПАПКИ
python trading_bot/strategy_evaluation.py trading_bot/reports/ИМЯ_ПАПКИ
python trading_bot/research_context.py ИМЯ_ПАПКИ_1 ИМЯ_ПАПКИ_2
python trading_bot/portfolio_research.py --tickers SBER LKOH GAZP
```

Для `strategy_evaluation.py` нужно минимум 180 календарных дней, для старого
`research.py` — 60. Проверяются фиксированные гипотезы, более поздний участок
не используется для выбора параметров. Но уже просмотренная история не
является полностью слепым тестом; RSI2 был добавлен после первых экспериментов.
Все результаты и исходные свечи сохраняются локально в папке исследования.

Дневной портфельный модуль — **отдельное исследование**, не профиль исполнения
в панели. Он выбирает два инструмента по положительному росту за 63 дневные
свечи выше SMA200, пересматривает раз в неделю, вкладывает максимум по 5% капитала.
Сигнал использует предыдущие дни, сделка — следующее открытие. Сравнивает ранний
участок, последние 90 дней, удвоенные затраты и пассивный портфель с целевыми
10% капитала. Лоты неделимы: реальные вложения могут быть меньше целевых.
Здесь нет внутридневных стопов старого робота; нет дивидендов и процентов.
Выбор нынешних компаний и короткая история ограничивают выводы. Отсутствие
сделок с нулевым результатом — отказ от риска, а не прибыльная стратегия.

## Docker

Настройки приложения считываются из смонтированного secret-файла, переменные
процесса имеют приоритет. Compose закрепляет `SANDBOX=true` и оба разрешения
заявок в `false`. Для самостоятельного разрешения Sandbox-исполнения можно
создать **локальный** файл `compose.override.yaml` и задать оба флага в
`services.panel.environment`; затем пересоздать контейнер. Даже тогда стратегия
не стартует автоматически: нужна отдельная кнопка или команда `--execute`.
Не меняйте localhost-привязку порта и не используйте это как публичный сервис.

Экспорт файлов из контейнера:

```bash
docker compose cp panel:/app/trading_bot/reports ./saved-reports
docker compose cp panel:/app/trading_bot/logs ./saved-logs
```

Эти копии могут содержать приватные данные; не добавляйте их в репозиторий.
Для команд CLI используйте `docker compose exec panel python trading_bot/main.py --help`.
Не запускайте второй экземпляр управления тем же профилем параллельно панели.

## Диагностика

- **UNAVAILABLE / DNS**: проверьте доступ к `sandbox-invest-public-api.tbank.ru:443`,
  DNS, VPN и прокси. Ошибка разрешения имени возникает до проверки токена.
- **UNAUTHENTICATED**: проверьте тип токена, срок и наличие лишних пробелов.
- **TLS / сертификат**: обновите pip и CA, настройте доверенный корпоративный CA;
  не отключайте проверку сертификатов.
- **Нет входов**: проверьте свежесть котировки, статус торгов, наличие завершённых
  свечей, сигнал, ограничения риска и стоимость одного лота.
- **Порт занят**: остановите прежний запуск панели перед запуском Docker или Python.
- **Профиль не переключается**: остановите робота и дождитесь окончания бэктеста.
- **Нет связи с API в контейнере**: проверьте DNS/прокси Docker. Healthcheck проверяет
  только HTTP-панель; её доступность не доказывает соединение с брокером.
